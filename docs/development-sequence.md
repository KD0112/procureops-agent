# Development Sequence

## 总原则

先建立不可绕过的 Harness，再实现一条单 Agent 采购闭环；只有对照评测证明有收益时，才引入多个专业 Agent。第二租户在第一租户闭环稳定后开始。

## Phase 0：Harness 基线（当前）

- RunContext、预算、截止时间和版本冻结
- Model Gateway 与 FakeModel
- Tool Gateway、RBAC、风险等级、重试和 fail-closed
- 审批参数哈希绑定、写操作幂等、追加式审计
- RAG 文档治理、Tenant Pack 和离线安全用例

验收：普通测试不调用付费模型；静态检查与安全不变量测试 100% 通过。

## Phase 1：确定性采购骨架

- SQLite 核心实体与迁移
- 采购任务状态机
- 金额、税费、运费和总成本计算器
- 目录、供应商、报价、库存与 PO 草稿模拟工具
- 一条固定输入到 PO 草稿的无模型 happy path

验收：任务可重启、可回放；重复执行不产生第二份草稿；金额使用 Decimal 并通过边界测试。

## Phase 2：单 Agent 闭环

- PDF、Excel、图片和文本 Intake
- 结构化字段提取与 Schema 校验
- 目录候选匹配和缺失字段追问
- 政策/风险检查与人工审批恢复
- 字段级证据链和任务页面/API

验收：黄金集正常任务完成率达到预设门槛；无证据关键字段无法进入 PO 草稿。

## Phase 3：受治理 RAG 与记忆

- 混合检索、Tenant/角色过滤、引用和过期控制
- 用户偏好候选、确认、纠错、删除和 TTL
- Prompt 注入与跨租户安全测试

验收：跨租户泄漏为 0；动态事实 RAG 命中为 0；未确认记忆使用率为 0。

## Phase 4：端到端评测与可观测性

- 100 条第一租户用例、轨迹评测、失败分类和回放
- 成本、模型/工具调用、P50/P95 延迟
- 版本对比与发布门禁

验收：安全不变量必须全过；业务指标不得以平均分掩盖高风险失败。

## Phase 5：多 Agent 对照实验

- A：单 Agent + 工具
- B：Supervisor + Intake/Catalog/Supplier/Policy 专业 Agent
- 使用相同用例、工具快照、预算和评分器对照

验收：只有 B 在质量、成本或可诊断性上有明确收益时才保留；否则项目诚实采用 A。

## Phase 6：第二租户迁移（暂缓）

仅替换 Schema、知识库、规则和工具适配器，工作流代码不复制。

验收：跨行业迁移不修改核心工作流；用自动化测试证明租户隔离和配置化差异。
