# 面试追问防守要点

## 为什么不是 LangChain / LangGraph？

不是因为框架“过时”，而是本项目要展示的核心是可审计执行合同：版本化 `RunContext`、状态迁移、工具权限、审批绑定、预算、幂等和回放。当前用显式 Python 状态机减少隐式运行时；若团队已有 LangGraph，也可以把它放在 orchestration 层，但不能绕开 Harness。

## 为什么多 Agent 最后没有默认启用？

架构选择由同一 100 条用例的 A/B 决定。当前两者质量、安全和证据覆盖相同，多 Agent 只增加消息与轻微延迟，因此默认单 Agent。保留 Supervisor 实验实现，是为了当未来长任务、权限分区或独立失败域产生可测收益时再启用。

## 队列是否 exactly-once？

不宣称 exactly-once。队列是 at-least-once：lease 过期后 Job 会被其他 Worker 重新领取；业务写入依靠租户级幂等键 + 请求哈希实现 effectively-once side effect。同键不同请求会冲突，而不是静默复用。

## LLM 能“自主进化”吗？

生产运行时禁止自动修改 Prompt、规则或代码。改进闭环是：收集人工纠错 → 构造离线用例 → A/B 评测 → 审批版本 → 发布 → 可回滚。首轮真实模型 5/10 暴露合同不清，显式 JSON Prompt 后同集达到 10/10，就是受治理改进的例子，而不是在线自修改。

## 记忆为什么不是聊天历史？

聊天历史既不可控也容易跨边界泄漏。记忆以 tenant + user 隔离，先写 candidate，用户确认后才可读；支持纠错链、删除、TTL 和敏感键拒绝。每次使用确认记忆都生成证据。

## RAG 为什么不能保存价格？

价格、库存、物流和订单状态有明确时效与系统真值，必须通过工具获得 `observed_at` / `valid_until`。RAG 只保存静态制度、产品手册和解释性资料，并执行租户/角色过滤与引用。

## SQLite 够企业级吗？

SQLite 是个人项目的本地 Profile，不是生产容量声明。企业深度来自约束、迁移、事务、租户键、审计、失败恢复和替换边界。生产迁移点是 PostgreSQL、对象存储和托管队列；领域模型和测试不应重写。

## 如何证明不是页面演示？

FastAPI、网页与命令行 Worker 共用同一 Repository、状态机、队列和 Tool Gateway。集成测试从 HTTP 创建任务，运行真实 Worker，验证暂停审批、角色拒绝、恢复、PO 幂等、上传和跨租户 404；页面没有直接写数据库的特殊路径。

## 当前最诚实的不足是什么？

合成数据不能代表真实目录匹配准确率；图片目前只做一条 Smoke；没有真实 ERP/供应商写接口；第二租户暂缓；SQLite 不提供分布式吞吐。这些是下一阶段验证项，不应在面试中包装成已完成能力。
