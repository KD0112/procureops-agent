# ProcureOps Agent：面试演示、讲解顺序与简历写法

## 30 秒项目介绍

我做了一个多租户企业采购 Agent。它不是聊天 Demo，而是从 PDF、Excel、图片或文本采购需求出发，完成目录匹配、供应商报价库存查询、物流询价、确定性成本计算、政策检查、人工审批和 ERP PO 草稿。系统有字段级证据、长期记忆、受治理持续学习、Harness、回放和 120 条端到端用例，并用工程机械与企业 IT 两个租户验证同一架构的跨行业迁移。

## 2 分钟架构介绍

先说明业务终点：系统只创建 PO 草稿，不付款、不正式下单。

然后按四层讲：

1. 语义层：Intake、目录匹配、Supplier Research 和 Policy Reviewer 处理不确定信息；
2. 决策层：状态机、Decimal 成本、供应商准入、审批角色和 PO 幂等由确定性代码负责；
3. 控制层：Harness 统一做 RunContext、预算、RBAC、审批绑定、超时、重试、审计和回放；
4. 数据层：静态制度进入 RAG，动态价格库存物流来自数据库或 ERP/供应商/物流工具。

最后讲最重要的架构判断：我对单 Agent 与两种多 Agent 路径做了同数据对照。多 Agent 当前没有带来质量或安全收益，所以默认单 Agent，而不是为了简历堆 Agent。

## 网站普通演示流程

### 启动

```powershell
cd "D:\new things\项目1\project2"
& ".\.venv\Scripts\python.exe" scripts\run_api.py
```

打开 `http://127.0.0.1:8030`。

### 工程机械租户

1. 保持“工程机械配件采购演示租户”和“采购申请人”；
2. 新建任务：`DEMO-HYD-PUMP-001 | 液压泵 | 2 | 台`；
3. 点击“运行下一项 Worker”；
4. 查看目录、供应商、物流、成本、证据和状态时间线；
5. 系统停在“待审批”；
6. 切换为“部门审批人”或满足当前门槛的另一个身份；
7. 批准后再次运行 Worker；
8. 查看 PO 草稿与幂等写入结果。

### 企业 IT 第二租户

1. 点击“切换身份”，租户选择“企业 IT 设备采购演示租户”；
2. 身份选择“采购申请人”；
3. 输入：`IT-LAP-DEV-14 | 研发笔记本 | 2 | 台`；
4. 重复 Worker、证据、审批和 PO 流程；
5. 强调页面和后端没有更换工作流，只更换了 Tenant Pack。

### 记忆演示

1. 用采购申请人创建文本：`IT-LAP-DEV-14 | 研发笔记本 | 1 | 台。以后优先最快交付`；
2. 运行 Worker 后打开“用户记忆”；
3. 展示它先是 candidate，未确认不会生效；
4. 用户确认后，新任务会把偏好用于允许范围内的供应商排序；
5. 展示纠错、删除和访问审计；
6. 强调偏好不能覆盖准入、审批、币种和权限。

### 受治理进化演示

1. 打开“进化治理”；
2. 提交失败或纠错反馈；
3. 从反馈创建 Prompt 候选；
4. 运行固定 Gold Set 回归；
5. 切换合规身份审批并发布；
6. 演示回滚；
7. 强调生产环境不允许 Agent 自改代码或 Prompt。

## ERP、供应商和物流 HTTP 演示

终端一：

```powershell
& ".\.venv\Scripts\python.exe" scripts\run_integration_sandbox.py
```

终端二：

```powershell
$env:PROCUREOPS_INTEGRATION_PROFILE="http_sandbox"
$env:PROCUREOPS_ERP_BASE_URL="http://127.0.0.1:8101"
$env:PROCUREOPS_SUPPLIER_BASE_URL="http://127.0.0.1:8101"
$env:PROCUREOPS_LOGISTICS_BASE_URL="http://127.0.0.1:8101"
$env:PROCUREOPS_INTEGRATION_API_KEY="local-only-not-a-secret"
& ".\.venv\Scripts\python.exe" scripts\run_api.py
```

演示时说明：8101 是独立企业系统契约模拟器。主应用通过真实 HTTP、服务鉴权、租户头、合同版本和 Pydantic Schema 访问它。PO 请求还带审批 subject hash 和 Idempotency-Key。生产 UAT 只需要切换 HTTPS Endpoint 与私密凭据。

## 建议的 8 分钟顺序

1. 0:00–0:45：业务问题和一句话定位；
2. 0:45–2:00：架构图与静态/动态事实边界；
3. 2:00–4:00：IT 租户创建任务、证据和审批暂停；
4. 4:00–5:00：切换身份审批并展示 ERP PO 草稿；
5. 5:00–6:00：记忆候选、确认和安全边界；
6. 6:00–7:00：100 + 20 条评测与单/多 Agent A/B；
7. 7:00–8:00：失败场景、生产差距和扩展方案。

## 简历项目标题

`ProcureOps Agent｜多租户企业采购询价与供应商协同平台`

## 简历项目描述

- 设计并实现 Harness-first 企业采购 Agent，将多格式采购需求转化为目录匹配、供应商/库存/物流查询、Decimal 成本计算、风险检查、HITL 审批与幂等 ERP PO 草稿的长流程任务。
- 构建用户级可治理长期记忆和受控持续学习闭环，支持候选确认、纠错、删除、TTL、投毒防护，以及反馈驱动的 Prompt 离线回归、合规发布与回滚。
- 实现单 Agent、Supervisor + 确定性专家和模型专业 Agent 三路对照；在同一 100 条评测集上根据质量、安全、延迟和成本决定默认架构，避免无收益的多 Agent 复杂度。
- 通过工程机械和企业 IT 两个 Tenant Pack 复用同一工作流，增加 20 条跨租户 E2E；实现 ERP、供应商、物流的 local/http_sandbox/http_enterprise 适配器及鉴权、超时、错误分类、Schema、审批绑定和幂等治理。
- 使用 FastAPI、Pydantic、SQLite、原生状态机与自建 Harness，CI 采用 FakeModel/MockTransport，不依赖付费模型；支持 Qwen 文本/视觉优先路由与 DeepSeek/Zhipu 降级。

## 简历数字如何说才准确

- 可以说：“120 条固定 E2E/跨租户案例，另有单元和集成测试”；
- 可以说：“关键安全用例通过率 100%，未审批 PO 写入为 0”；
- 可以说：“测试覆盖率达到项目门禁要求”；
- 不要说：“真实企业采购准确率 100%”；
- 不要说：“已接入某公司生产 ERP”；
- 不要说：“Agent 会在生产中自动进化代码”。
