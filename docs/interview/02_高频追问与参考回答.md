# ProcureOps Agent：高频面试追问与参考回答

## 1. 这和普通 RAG 聊天机器人有什么区别？

普通 RAG Demo 的终点通常是一段文本。本项目的终点是数据库和 ERP 中可核验的 PO 草稿状态。它有确定性状态机、动态工具、审批、幂等、证据、Outbox、回放和环境结果评测，模型回答只是过程中的一部分。

## 2. 为什么用采购场景？

采购同时包含非结构化输入、静态制度、动态价格库存、多系统协同、金额计算、高风险写操作和人工审批，能完整展示企业 Agent 落地问题，而不是只展示 Prompt 能力。

## 3. 你所谓“自主进化”具体是什么？

我没有让生产 Agent 自改代码。线上反馈只能形成候选，候选先进入固定 Gold Set 离线回归，安全率和关键回归门禁通过后，由不同合规身份审批、人工发布，并保留回滚。更准确的名字是“受治理持续学习”。

## 4. 用户记忆为什么不能直接拼进 Prompt？

确认只代表用户同意，不代表这条记忆有权限改变业务规则。我的记忆先经过白名单和完整性校验，再映射成有限决策字段。目前只能影响已准入供应商的排序，不能改变审批、准入、币种和权限。

## 5. 如何防止跨用户或跨租户记忆泄漏？

所有读写都要求 `tenant_id + user_id`，数据库查询带复合过滤，API 身份从服务端 Session 和成员表解析。测试覆盖另一个租户、另一个用户、删除、过期和数据库篡改。

## 6. 为什么有多 Agent，但默认还是单 Agent？

我先建立单 Agent 基线，再用同一 100 条数据比较确定性专业 Agent 和模型专业 Agent。当前多 Agent 没有质量或安全收益，却增加延迟、调用和调试复杂度，所以默认单 Agent。专业组件保留作为实验和诊断边界。

## 7. Supervisor 有什么权力？

Supervisor 可以路由窄职责审阅和合并 advisory 结果，但不能绕过状态机、Tool Gateway、权限、审批和幂等。确定性工作流是唯一权威决策者。

## 8. 为什么不用 LangChain/LangGraph？

LangChain/LangGraph 并没有“退出主流”，但企业价值不在框架名称。本项目用原生状态机和自建 Harness，让状态、工具和模型协议可替换，减少框架耦合。需要时仍可把某个 Agent 适配到 LangGraph，而不用重写领域和治理层。

## 9. 你的 Harness 和日志工具有什么区别？

日志只记录发生了什么。Harness 在调用前后执行权限、租户、预算、审批、参数、幂等、超时和重试决策，并生成结构化审计与回放记录。它是控制面，不只是可观测性。

## 10. 为什么动态价格不能放进 RAG？

向量索引没有交易级新鲜度和一致性语义。当前价格、库存、物流和订单状态必须来自数据库或工具，并携带观察时间和有效期；RAG 只放制度、手册和目录解释。

## 11. 如何保证金额计算正确？

金额使用 Decimal，不让 LLM 计算。行金额、税、运费和汇总均由确定性函数完成，测试覆盖四舍五入、库存边界和总额一致性。

## 12. 审批如何防止“批准 A，执行 B”？

审批绑定 `tenant_id + task_id + action + subject_hash`。subject 包含供应商、数量、价格、总额和 PO 载荷；任何字段变化都会改变哈希，使旧审批失效。

## 13. 为什么采购申请人不能审批自己的任务？

这是 maker-checker 职责分离。API 会比较任务创建者和审批者；即使角色足够，同一个身份也不能自批。

## 14. PO 写入怎样避免重复？

Tool Gateway 要求写工具提供幂等键；数据库对 `tenant_id + idempotency_key` 建唯一约束；HTTP ERP 还接收同一个 Idempotency-Key。相同键相同请求返回旧结果，相同键不同请求报冲突。

## 15. 如果 ERP 已成功，但响应前网络断了怎么办？

上游用同一个 Idempotency-Key 重放，ERP 应返回同一草稿；本地再保存外部回执投影。写工具不做无脑自动重试，避免未知结果下重复副作用。生产还应结合目标 ERP 的幂等 SLA 和对账接口。

## 16. Tool Gateway 何时重试？

只重试超时、网络失败、429 和明确 5xx。4xx、参数错误、权限拒绝、审批缺失、租户错配和 Schema 错误都是永久失败。

## 17. 如何防止 SSRF？

Base URL 只来自服务端环境配置，模型和用户不能传 URL；非回环地址只允许 HTTPS；URL 中禁止用户信息、查询和片段；HTTP 客户端不跟随重定向。

## 18. 外部系统返回了另一个租户的数据怎么办？

所有请求带 `X-Tenant-ID`，响应必须回显相同 tenant_id。适配器在 Pydantic 业务校验前先做租户一致性检查，不一致直接永久失败。

## 19. 你真的接入真实 ERP 了吗？

我完成了生产形态 HTTP 适配器、服务鉴权、合同版本、超时、Schema、租户、审批和幂等，并提供独立本机沙箱。因为没有企业提供 UAT Endpoint、凭据和字段合同，我不会声称连接了某家公司的生产 ERP。拿到 UAT 信息后切换 `http_enterprise` 即可进入联调。

## 20. 第二租户如何证明不是复制代码？

两个租户调用同一个 Workflow、Harness、Agent、数据库 Repository 和评测 Runner。差异只在 Tenant Pack、产品目录、规则、知识和适配器配置。工程机械租户查询 IT SKU 会进入追问，反向也隔离。

## 21. RAG 如何做租户和角色过滤？

知识文档有强制元数据：tenant、status、classification、allowed_roles、版本和动态事实标记。检索先做 ACL 过滤，再做关键词与确定性稠密混合评分，并返回 citation 和 Corpus Hash。

## 22. 为什么本地用 SQLite？

用户要求不使用 Docker/WSL2，SQLite 让个人项目可复现。代码保留 Repository 和迁移边界，生产方案会切 PostgreSQL，增加 RLS、连接池、备份、HA 和真实异步 Worker。面试中不会把 SQLite 说成最终生产选型。

## 23. Outbox 解决什么问题？

任务与 `work.requested` 在同一数据库事务提交，避免“任务已创建但消息没发出”。Outbox 重发再通过队列幂等键避免重复 Job。两者处理不同故障窗口。

## 24. 端到端评测为什么不只比较最终文本？

企业 Agent 可能说“已完成”，但数据库没有正确 PO。我的 grader 检查轨迹、安全不变量、证据覆盖、审批角色、工具调用和最终数据库状态，并保存回放包。

## 25. 100 条用例包括什么？

40 正常、20 模糊、15 工具失败、15 攻击和 10 审批边界。第二租户另有 20 条 IT/隔离用例，包含正常、追问、瞬时/永久故障、Prompt Injection、租户逃逸和三档审批。

## 26. 为什么 CI 不调用真实模型？

付费模型有成本、网络和非确定性，不能作为普通单元测试基础。CI 用 FakeModel 和 MockTransport 验证协议与治理；真实 Qwen/DeepSeek 评测是显式 opt-in，报告单独保存。

## 27. 千问如何接入？

Qwen 文本和视觉走 DashScope OpenAI-compatible 适配器，Model Router 支持 Qwen 优先、DeepSeek/Zhipu 降级和熔断。密钥只从环境读取；未配置时不会进入路由，也不会伪造真实得分。

## 28. Prompt Injection 如何处理？

外部文档、历史、RAG 和工具结果都视为不可信数据。模型输出只产生候选或 advisory；权限、审批、工具白名单和状态机在模型之外。攻击测试验证“忽略审批直接下单”仍必须停在审批。

## 29. 当前最需要的下一步是什么？

如果要继续走向真实落地，优先获取一套脱敏采购数据和一个 ERP UAT 接口，完成字段映射、契约测试、对账与真实评测；随后把 SQLite Profile 替换为 PostgreSQL + 企业 SSO，而不是继续增加更多 Agent。

## 30. 这个项目最体现你的哪项能力？

不是会调用某个模型，而是能把不确定模型嵌入有状态、高风险、可审计的业务流程，并用评测数据决定架构复杂度。这更接近中大型企业 Agent 工程岗位的实际工作。
