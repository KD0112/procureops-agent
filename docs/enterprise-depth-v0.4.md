# ProcureOps v0.4：企业深化 1–5 验收说明

## 结论

v0.4 完成了五项深化：模型路由与千问准备、受限 Supplier Research Agent、可治理记忆、Prompt 回归门禁、本地身份与事务 Outbox。实现仍坚持“模型建议、工具取事实、确定性代码决策、高风险动作人工批准”。

## 1. Qwen、Gold Set、路由、降级与熔断

- DashScope 文本和视觉请求都使用 OpenAI-compatible 客户端，密钥只从环境读取。
- 默认路由为文本 `qwen → deepseek`、视觉 `qwen → zhipu`；未配置的提供方不会进入运行路由。
- 每次实际提供方尝试都经过 Harness，分别计算模型调用、Token 和费用预算，并记录无敏感数据的审计事件。
- 同一提供方连续失败达到阈值后熔断；恢复窗口后允许半开式重试。预算耗尽与截止时间不会被降级逻辑掩盖。
- `data/evals/model_gold_v1.jsonl` 固定 20 条文本 Gold Set，包含中文数字、英文、字段换序、Prompt 注入、XML 注入、输出劫持与防幻觉边界。
- 本机未配置 DashScope 密钥，所以只验证了适配协议、路由和失败恢复，不声称拥有真实千问准确率。

面试追问：为什么不能把降级写在 HTTP 客户端里？因为那会漏记第二次真实模型调用的预算和审计；本项目把降级放在 Harness 路由层。

## 2. 受限 Supplier Research Agent

- Agent 使用最多 3 步的 plan-act-observe 循环。
- 允许动作只有 `logistics_quote` 和 `finish`，无法执行 PO、审批或任意工具。
- 动态时效和运费来自 `logistics_quotes` 数据库工具，并保存观察时间、有效期和证据定位。
- LLM 推荐只作为可诊断信息；最终选择仍由确定性 `PreferenceDecisionEngine` 在已准入供应商集合内完成。
- 越权动作、结构错误、无物流证据结束、模型不可用或超预算都会 fail-safe 到确定性路径。

面试追问：这是不是为了堆多 Agent？不是。相同 100 条数据上，多 Agent 没有质量收益，默认仍运行单 Agent；专业 Agent 仅作为可控实验路径保留。

## 3. 记忆决策、完整性与投毒防护

- 优先级固定为：任务显式输入 > 用户已确认记忆 > 租户默认值。
- 当前允许记忆影响供应商排序策略；审批阈值、准入、风险等级、币种和权限是保护字段。
- 候选必须经用户确认；支持纠错、软删除、TTL、租户/用户隔离和来源去重。
- 值大小限制为 2048 字节；指令型内容、系统标签、绕过审批或自动下单表达会被拒绝。
- 每条记录有内容完整性哈希；数据库值被篡改后读取失败并产生 `integrity_mismatch` 审计。
- 访问审计只存动作、决策和元数据哈希，不重复保存偏好明文。

面试追问：为什么确认过的记忆仍不能直接进入 Prompt？确认解决用户同意问题，不解决权限边界；记忆必须先进入确定性决策映射。

## 4. Prompt 基线/候选回归门禁

- 反馈只能形成候选，不能修改运行中 Prompt。
- 候选与当前基线使用同一 20 条版本化 Gold Set 做离线 FakeModel 回归。
- 发布门禁要求：质量不低于基线、安全通过率 100%、关键回归数量为 0、静态契约完整且不含疑似密钥。
- 报告保存数据集哈希、基线/候选 Prompt 哈希、逐案例结果、质量差值和门禁阈值。
- 候选提出者不能审批自己的候选；只有合规角色能审批、发布与回滚。

边界：FakeModel 门禁保证 CI 可重复和不产生费用，不等于真实模型质量。真实发布前应追加 `gold_regression_live_model_v1` 证据。

## 5. 服务端身份、maker-checker 与事务 Outbox

- 业务 API 只接受 Bearer 会话；角色从 `tenant_memberships` 服务端读取。测试模式必须显式打开才能使用请求头身份。
- 单机演示采用免密码身份选择器，首次自动进入采购人；切换身份只提交固定的本机用户 ID，不能提交角色。会话只保存 Token 哈希，支持到期与注销。
- 采购任务创建者不能审批或拒绝自己的任务；Prompt 提出者不能审批自己的候选。
- 采购任务、可选上传元数据和 `work.requested` Outbox 事件在同一个 SQLite 事务中提交。
- Outbox 投递到租约队列时使用相同幂等键；进程在入队后、标记已投递前崩溃，重放只会复用原 Job。
- Worker 每次取任务前先排空 `pending/dispatching` Outbox，保证本机重启后恢复。

边界：免密码身份只适用于不联网的个人演示环境，不构成真实人员认证。企业部署必须在这一服务端角色边界前接公司 SSO/OIDC。

面试追问：为什么既有 Outbox 又有幂等队列？Outbox解决“业务提交了但消息没发出”，幂等键解决“崩溃重发导致重复 Job”。两者处理的是不同故障窗口。

## 验收证据

- 自动化测试：94 条，覆盖率 90%。
- E2E：单 Agent、确定性多 Agent、FakeModel LLM 多 Agent 均为 100/100，安全率 100%。
- LLM 多 Agent：450 次 Harness 模型调用、费用 0，未产生质量收益，因此默认选择单 Agent。
- SQLite：`integrity_check=ok`，外键违规为 0，迁移到 `006_enterprise_depth`，四条关键查询均使用索引。
- 报告：`reports/latest_*` 与 `reports/latest_sqlite_verification.json`。
